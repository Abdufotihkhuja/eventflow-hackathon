# Просмотр профилей, подписки, события и блоги — кейсы и сценарии

Описание сценариев для авторизованных и неавторизованных пользователей: просмотр профиля организатора, подписка на организатора, просмотр текущих/прошедших событий и блогов.

---

## 1. Профиль организатора

### 1.1 Неавторизованный пользователь

| Действие                                  | Доступ | Эндпоинт                              | Результат                                                               |
| ----------------------------------------- | ------ | ------------------------------------- | ----------------------------------------------------------------------- |
| Просмотр полного профиля организатора     | Нет    | `GET /organizations/:id/public`       | 401 Unauthorized — требуется JWT                                        |
| Просмотр публичной статистики организации | Да     | `GET /public/organizations/:id/stats` | Агрегированные данные (события, подписчики и т.д.) без флага «подписан» |

**Flow:** Гость заходит на страницу организатора → видит только статистику через публичный API; для карточки организатора (название, описание, лого, isFollowing) нужна авторизация.

### 1.2 Авторизованный пользователь (тип USER)

| Действие                                 | Эндпоинт                              | Результат                                                                                                                      |
| ---------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Просмотр публичного профиля организатора | `GET /organizations/:id/public`       | Полный публичный профиль: название, описание, лого, сайт, адрес, верификация, `followersCount`, `eventsCount`, **isFollowing** |
| Подписаться на организатора              | `POST /organizations/:id/follow`      | 204 при успехе; 409 если уже подписан                                                                                          |
| Отписаться                               | `DELETE /organizations/:id/unfollow`  | 204                                                                                                                            |
| Проверить подписку                       | `GET /organizations/:id/is-following` | `{ isFollowing: boolean }`                                                                                                     |

**Flow:** Пользователь открывает страницу организатора → вызывается `GET /organizations/:id/public` → в ответе `isFollowing`; кнопка «Подписаться»/«Отписаться» и счётчик подписчиков отображаются согласно ответу.

### 1.3 Авторизованный пользователь (ORGANIZATION / MEMBER)

Профиль «своей» организации — через `GET /workspace/me`. Просмотр чужого организатора как у USER — `GET /organizations/:id/public` (если в ролях разрешён USER или отдельно не ограничено).

---

## 2. Подписка на организатора

Доступна только авторизованным пользователям с типом **USER**. ORGANIZATION и MEMBER не подписываются на других организаторов через этот API.

| Кейс                         | Шаги                                        | Ответ API                     |
| ---------------------------- | ------------------------------------------- | ----------------------------- |
| Успешная подписка            | USER → `POST /organizations/:id/follow`     | 204                           |
| Уже подписан                 | Повторный `POST .../follow`                 | 409 Conflict                  |
| Отписка                      | USER → `DELETE /organizations/:id/unfollow` | 204                           |
| Организация не найдена       | `POST/DELETE` с несуществующим `:id`        | 404                           |
| Гость нажимает «Подписаться» | Нет токена                                  | 401 → фронт редирект на логин |

**Flow подписки:** Страница организатора → кнопка «Подписаться» → при наличии JWT запрос `POST .../follow` → обновить UI (кнопка «Отписаться», инкремент счётчика); при 401 — показать модалку входа/редирект на логин.

## 3. Просмотр событий (текущие и прошедшие)

### 3.1 Публичный каталог (все события платформы)

Доступно всем (в т.ч. без авторизации).

| Эндпоинт             | Кто | Описание                                               |
| -------------------- | --- | ------------------------------------------------------ |
| `GET /public/events` | Все | Список опубликованных событий с пагинацией и фильтрами |

**Query-параметры (фрагмент):**

- `filter`: `upcoming` | `past` | `all` — предстоящие, прошедшие или все
- `page`, `limit`, `search`, `city`, `format`, `type`, `featured`

**Кейсы:**

| Кейс                            | Параметры                                                         | Результат                                              |
| ------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------ |
| Только предстоящие              | `filter=upcoming` (по умолчанию)                                  | События с `endDate >= now`, статус PUBLISHED           |
| Только прошедшие                | `filter=past`                                                     | События с `endDate < now`, статусы PUBLISHED/COMPLETED |
| Все                             | `filter=all`                                                      | Без фильтра по дате                                    |
| События организатора в каталоге | Общий список; при клике на организатора — переход на его страницу | —                                                      |

**Flow:** Лендинг/каталог → `GET /public/events?filter=upcoming` (или `past`) → список карточек; переключение вкладок «Предстоящие» / «Прошедшие» меняет только `filter`.

### 3.2 Одно событие по ID или slug

| Эндпоинт                           | Кто | Поведение                                                                                                                                   |
| ---------------------------------- | --- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /public/events/:id`           | Все | Optional JWT: без токена — только данные события; с токеном — в ответе дополнительно **myRegistration** (если пользователь зарегистрирован) |
| `GET /public/events/by-slug/:slug` | Все | Аналогично по slug                                                                                                                          |

**Кейсы:**

| Кейс                                        | Авторизация | Результат                                                    |
| ------------------------------------------- | ----------- | ------------------------------------------------------------ |
| Гость открывает карточку события            | Нет         | Полная публичная информация, без блока «Вы зарегистрированы» |
| USER открывает карточку, он зарегистрирован | JWT         | В ответе есть `myRegistration` (статус, QR и т.д.)           |
| USER открывает карточку, не зарегистрирован | JWT         | `myRegistration: null` или отсутствует                       |

### 3.3 События конкретного организатора (страница организатора)

Только для авторизованных пользователей с типом **USER**.

| Эндпоинт                               | Query                                        | Описание                                                     |
| -------------------------------------- | -------------------------------------------- | ------------------------------------------------------------ |
| `GET /events/organizations/:id/events` | `status=UPCOMING` \| `PAST`, `page`, `limit` | Предстоящие или прошедшие опубликованные события организации |

**Flow:** Страница организатора (после входа) → два блока «Предстоящие события» и «Прошедшие события» → запросы `GET /events/organizations/:id/events?status=UPCOMING` и `...?status=PAST`.

**Ограничение:** Неавторизованный пользователь не может получить события по организатору через этот endpoint (401). Для гостя на странице организатора можно показывать только данные из `GET /public/organizations/:id/stats` и предлагать войти для просмотра событий организатора (или доработать API и добавить публичный `GET /public/organizations/:id/events`).

## 4. Просмотр блогов

Вся выдача блога — только опубликованные статьи; доступ без авторизации.

### 4.1 Список статей

| Эндпоинт    | Кто | Описание                                              |
| ----------- | --- | ----------------------------------------------------- |
| `GET /blog` | Все | Список опубликованных статей с пагинацией и фильтрами |

**Query (основное):** `page`, `limit`, `search`, `organizationId`, `tagId`, `tagIds[]`, `publishedAfter`, `publishedBefore`, `minReadingTime`, `maxReadingTime`, `sortBy`, `sortOrder`.

**Кейсы:**

| Кейс                            | Параметры               | Результат                        |
| ------------------------------- | ----------------------- | -------------------------------- |
| Все статьи платформы            | Без `organizationId`    | Все опубликованные               |
| Блог организатора               | `organizationId=<uuid>` | Только статьи этой организации   |
| Поиск                           | `search=...`            | По заголовку и краткому описанию |
| По тегу / дате / времени чтения | Соответствующие query   | Фильтрация по выбранным полям    |

### 4.2 Одна статья

| Эндпоинт                  | Кто | Примечание                                |
| ------------------------- | --- | ----------------------------------------- |
| `GET /blog/:id`           | Все | По ID, увеличивается счётчик просмотров   |
| `GET /blog/by-slug/:slug` | Все | По slug, увеличивается счётчик просмотров |

**Flow:** Каталог статей → `GET /blog` (опционально `organizationId` для страницы организатора) → карточки; клик по статье → `GET /blog/by-slug/:slug` или `GET /blog/:id` → отображение контента.

## 6. Рекомендации по UX

1. **Страница организатора для гостя:** показывать статистику (`/public/organizations/:id/stats`), блок «Войдите, чтобы подписаться и видеть события организатора»; не показывать кнопку «Подписаться» без логина.
2. **События организатора для гостя:** при необходимости — ввести публичный `GET /public/organizations/:id/events` с фильтром upcoming/past, чтобы не требовать авторизацию только для просмотра событий организатора.
3. **Карточка события:** при наличии JWT опционально передавать его в запрос к `GET /public/events/:id` или `by-slug/:slug`, чтобы сразу показывать статус регистрации и QR.

## 7. Переход на страницу профиля организатора

**URL:** `/organizers/[id]`, где `id` — UUID организации.

**Точки входа (как пользователь попадает на страницу):**

| Место                                                          | Поведение                                                                                                                                                                                                     |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Карточка события** (каталог, лендинг, страница организатора) | В блоке «Организатор» внизу карточки: имя организатора — ссылка на `/organizers/[organizationId]`. Клик по блоку ведёт в профиль организатора; клик по остальной области карточки — на страницу события.      |
| **Страница события** (hero)                                    | Рядом с кнопкой «Подписаться»: текст «Организатор: _имя_» — ссылка на `/organizers/[organizationId]`.                                                                                                         |
| **Блок «Ещё события»** на странице события                     | В каждой строке под названием события: имя организатора — ссылка на `/organizers/[organizationId]`.                                                                                                           |
| **Страница статьи блога** (`/blog/[slug]`)                     | Имя автора (организатора) в шапке статьи и в карточке автора — ссылка на `/organizers/[organizationId]`; отдельная ссылка «Профиль организатора →» в карточке автора (при наличии `organizationId` у статьи). |
| **Прямой URL**                                                 | Переход по ссылке или из закладок: `https://.../organizers/{uuid}`.                                                                                                                                           |

Данные для ссылки берутся из API: в ответах событий (`GET /public/events`, `GET /public/events/:id`, `GET /events/organizations/:id/events`) поле `organization.id` передаётся на фронт; в сущности события хранится как `organizationId` (карточки) или `event.organization.id` (страница события).
