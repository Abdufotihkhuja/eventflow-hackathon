# Динамическая карточка Hero Showcase на главной странице

## Проблема

Карточка справа на главной странице всегда показывала предложение войти, даже когда пользователь был авторизован.

## Решение

Реализована умная логика отображения карточки в зависимости от состояния пользователя:

### 1. **Неавторизованный пользователь** - `HeroShowcaseGuest`
Показывается карточка с:
- Размытым превью QR-билета
- Призывом войти или зарегистрироваться
- Кнопками "Войти" и "Создать аккаунт"
- Социальным доказательством (12 800+ участников)

### 2. **Авторизованный без регистраций** - `HeroShowcaseEmpty`
Показывается карточка с:
- Популярным событием для регистрации
- Превью изображения события
- Деталями: дата, место, количество участников
- Кнопкой "Зарегистрироваться" на это событие
- Альтернативной кнопкой "Посмотреть все мероприятия"
- Списком преимуществ после регистрации

### 3. **Авторизованный с активными регистрациями** - `HeroShowcaseTicket`
Показывается билет на ближайшее событие:
- QR-код для входа
- Детали события (название, дата, время, место)
- Статус регистрации (зарегистрирован/подтверждён/посетил)
- Обратный отсчет до события
- Кнопки "Экспорт" и "Календарь"

## Технические детали

### Изменения в `landing-hero.tsx`

#### Добавлены импорты:
```typescript
import { useCurrentUserQuery, useUserEventsQuery } from "@shared/lib/hooks";
import type { UserEventItem } from "@shared/api/userEventsService";
```

#### Реализована функция-адаптер:
```typescript
function userEventToTicket(userEvent: UserEventItem): EventTicket
```
Преобразует данные из API (`UserEventItem`) в формат компонента билета (`EventTicket`).

#### Логика определения состояния:
1. **Проверка авторизации** через `useCurrentUserQuery()`
2. **Получение регистраций** через `useUserEventsQuery()` с фильтром `APPROVED`
3. **Фильтрация актуальных событий** - показываем только те, что не прошли или прошли менее 24 часов назад
4. **Выбор ближайшего события** - первое в отсортированном списке

### Изменения в `hero-showcase-empty.tsx`

#### Добавлен функционал:
- Загрузка популярного события через `usePublicEventsQuery()`
- Отображение карточки события с изображением
- Детали: дата, место, количество участников
- Прямая ссылка на регистрацию

#### Улучшения UX:
- Если популярное событие не загрузилось - показывается fallback
- Красивая карточка с hover-эффектами
- Списо преимуществ регистрации

## API интеграция

### Используемые endpoints:

1. **GET** `/api/v1/account/me` - проверка авторизации
   - Хук: `useCurrentUserQuery()`
   
2. **GET** `/api/v1/account/me/events?filter=APPROVED` - получение регистраций
   - Хук: `useUserEventsQuery({ params: { filter: "APPROVED" } })`
   
3. **GET** `/api/v1/events/public?limit=1&sortBy=popularity` - популярное событие
   - Хук: `usePublicEventsQuery({ page: 1, limit: 1, sortBy: "popularity" })`

## Логика фильтрации событий

```typescript
const upcomingEvents = useMemo(() => {
  if (!eventsData?.data) return [];
  
  const now = new Date();
  return eventsData.data.filter((eventItem) => {
    const eventDate = new Date(eventItem.event.startDate);
    const hoursAgo = (now.getTime() - eventDate.getTime()) / (1000 * 60 * 60);
    return hoursAgo < 24; // Событие актуально если прошло менее 24 часов
  });
}, [eventsData]);
```

## Состояния загрузки

Компонент корректно обрабатывает все состояния загрузки:

1. **Загрузка данных пользователя** - показывается `HeroShowcaseGuest`
2. **Загрузка событий** - показывается `HeroShowcaseEmpty`
3. **Данные загружены** - показывается соответствующий компонент

## Тестирование

### Сценарии для проверки:

1. ✅ Пользователь не авторизован → показывается HeroShowcaseGuest
2. ✅ Пользователь авторизован, нет регистраций → показывается HeroShowcaseEmpty с популярным событием
3. ✅ Пользователь авторизован, есть активная регистрация → показывается HeroShowcaseTicket с QR
4. ✅ Пользователь авторизован, регистрация на прошедшее событие (>24ч) → показывается HeroShowcaseEmpty
5. ✅ Пользователь авторизован, регистрация на событие которое только что прошло (<24ч) → показывается HeroShowcaseTicket
