# Локализация дат и времени

## Принцип

**Backend присылает время в формате ISO 8601.** Например: `2025-02-14T12:00:00.000Z`.

**Особенность agendaItems:** бэкенд может хранить локальное время события с суффиксом Z (ошибка): `1970-01-01T22:30:00.000Z` = 22:30 в городе события. В таком случае используется `parseAgendaTimeAsLocal()` для корректной интерпретации.

При отображении: **страница события** (Когда, Программа, Регистрация до) — в таймзоне события; **остальные страницы** — в локальном времени пользователя.

## Использование утилит

Все утилиты в `@shared/lib/date`:

| Функция | Назначение |
|---------|------------|
| `parseUtcIso(isoString)` | Парсит ISO-строку как UTC, возвращает `Date` |
| `formatUtcToLocalDate(isoString, options?)` | Дата для отображения: «14 февраля 2025» |
| `formatUtcToLocalDateTime(isoString, options?)` | Дата и время: «14 февраля 2025, 15:00» |
| `formatUtcToLocalTime(isoString, options?)` | Только время: «15:00» |
| `toLocalDateKey(date)` | YYYY-MM-DD в локальной дате для группировки (вместо `toISOString().split("T")[0]`) |
| `toUtcIsoString(value)` | Нормализует строку для отправки в API (добавляет Z при необходимости) |
| `parseAgendaTimeAsLocal(dateStr, timeStr, timezone)` | Интерпретирует date+time как локальное время события (для agendaItems с форматом 1970-01-01T…) |

## Правила

1. **Никогда не отображать ISO-строку напрямую** — пользователь видит UTC.
2. **Для группировки по дате** — использовать `toLocalDateKey(date)`, а не `date.toISOString().split("T")[0]` (последнее даёт UTC-дату).
3. **Intl.DateTimeFormat** — `timeZone: undefined` для локального времени пользователя; на странице события (Когда, Программа, Регистрация до) используется `event.logistics.timezone`.
4. **При отправке в API** — использовать `toUtcIsoString()` для полей даты.
