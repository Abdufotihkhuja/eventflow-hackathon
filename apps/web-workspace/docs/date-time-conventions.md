# Конвенции по дате и времени (фронтенд)

## Исходные данные с API

- Все даты/время с API считаются **UTC** в формате **ISO 8601 с суффиксом Z** (например `2024-01-15T12:00:00.000Z`).
- Парсинг: `new Date(isoString)` — корректно интерпретирует UTC.

## Вывод пользователю

- При выводе переводим в **локальное время пользователя**:
  - **Intl.DateTimeFormat** без опции `timeZone` (или с явной локалью) — по умолчанию используется часовой пояс браузера.
  - **date-fns** `format(new Date(isoString), ...)` — использует локальное время.
  - **toLocaleString() / toLocaleDateString()** — локальное время.

## Утилиты в проекте

- **`@shared/lib`**: `formatDate`, `formatTime` — дата/время в локальном времени; `toDateTimeLocalValue(iso)` — значение для `<input type="datetime-local">` (UTC → локальные `YYYY-MM-DDTHH:mm`); `parseCalendarDate(dateOnly)` — парсинг строки YYYY-MM-DD как календарного дня в локальной зоне; **`toISO8601Z(date)`** — для отправки дат на API (всегда строка с Z или `undefined`).
- В формах редактирования событий для полей datetime-local используется `toDateTimeLocalValue`, чтобы в инпуте отображалось то же мгновение в часовом поясе пользователя, а не UTC.
- Извлечение времени из ISO для отображения (например в программе мероприятия): локальные `getHours()`/`getMinutes()`, не `getUTCHours()`/`getUTCMinutes()`.

## Отправка на API

- Бэкенд **требует явную таймзону**: дата-время без суффикса Z (например `2025-06-15T10:00:00`) приводит к **400** от валидатора.
- Всегда отправлять даты в **ISO 8601 с Z** (UTC). Использовать утилиту **`toISO8601Z(date)`** из `@shared/lib`: она принимает строку из `datetime-local` или Date и возвращает строку с Z; для пустых значений — `undefined`.
