# Поддержка многодневных событий в агенде

## Описание

Добавлена полная поддержка создания программы (агенды) для многодневных событий. Организатор теперь может выбирать конкретный день при добавлении элемента программы, а элементы автоматически группируются по датам.

## Что изменилось

### 1. Обновлены типы API (`agenda.types.ts`)

**Добавлено обязательное поле `date`:**

```typescript
export type CreateAgendaItemRequest = {
  date: string // Дата проведения (YYYY-MM-DD) — для многодневных событий
  title: string
  type: AgendaItemType
  startTime: string // Формат HH:MM (например: "09:00")
  duration: number
  sortOrder: number
  // ... остальные поля
}

export type AgendaItem = {
  id: string
  eventId: string
  date: string // Дата проведения (YYYY-MM-DD)
  title: string
  // ... остальные поля
}
```

### 2. Расширен компонент `AgendaManager`

**Новые пропсы:**
- `startDate: string` — дата начала события
- `endDate: string` — дата окончания события

**Новый функционал:**
- Автоматическое вычисление списка дней события
- Группировка элементов программы по датам
- UI выбора даты при создании/редактировании элемента (для многодневных событий)

### 3. UI изменения

#### Выбор даты в форме

Для многодневных событий (когда `startDate !== endDate`) в форме создания/редактирования элемента программы появляется селектор даты:

```
День проведения *
┌─────────────────────────────────┐
│ День 1 — 20 января             │ ▼
└─────────────────────────────────┘
```

#### Группировка по дням

Элементы программы автоматически группируются и отображаются по дням:

```
📅 День 1 — 20 января ─────────────────

┌───────────────────────────────────────┐
│ 🎤 Открытие конференции              │
│ 09:00 - 10:00 • 60 мин               │
└───────────────────────────────────────┘

┌───────────────────────────────────────┐
│ 📊 Презентация новых возможностей    │
│ 10:30 - 12:00 • 90 мин               │
└───────────────────────────────────────┘

📅 День 2 — 21 января ─────────────────

┌───────────────────────────────────────┐
│ 🎓 Воркшоп для начинающих            │
│ 09:00 - 12:00 • 180 мин              │
└───────────────────────────────────────┘
```

Для однодневных событий заголовки дней не отображаются.

## Структура API запроса

### POST `/api/v1/events/{eventId}/agenda`

```json
{
  "date": "2026-01-22",      // День проведения (YYYY-MM-DD)
  "title": "Открытие",
  "type": "KEYNOTE",
  "startTime": "10:00",      // Время начала (HH:MM)
  "duration": 90,            // Длительность в минутах
  "sortOrder": 1,
  "description": "Торжественное открытие конференции",
  "location": "Главный зал",
  "speakerIds": ["uuid-1", "uuid-2"]
}
```

### Ответ (AgendaItem)

```json
{
  "id": "uuid",
  "eventId": "event-uuid",
  "date": "2026-01-22",
  "title": "Открытие",
  "type": "KEYNOTE",
  "startTime": "10:00",
  "duration": 90,
  "location": "Главный зал",
  "sortOrder": 1,
  "speakers": [
    { "id": "uuid-1", "name": "Иван Петров" },
    { "id": "uuid-2", "name": "Мария Сидорова" }
  ],
  "createdAt": "2026-01-15T12:00:00Z",
  "updatedAt": "2026-01-15T12:00:00Z"
}
```

## Примеры использования

### Однодневное событие

Если событие проходит в один день:
- Поле выбора даты **скрыто** (используется `startDate` автоматически)
- Заголовки дней **не отображаются**
- Программа выглядит как обычный список

### Многодневное событие (например, 3 дня)

1. При добавлении нового элемента:
   - По умолчанию выбирается **первый день** события
   - Пользователь может выбрать любой другой день из выпадающего списка

2. При редактировании:
   - Текущая дата элемента отображается в селекторе
   - Можно переместить элемент на другой день

3. Отображение:
   - Программа разделена визуально по дням
   - Каждый день имеет заголовок: "День N — дата"
   - Пустые дни показывают сообщение: "Программа для этого дня пока не добавлена"

## Сортировка элементов

Элементы программы сортируются в следующем порядке:
1. **По дате** (`date`) — сначала более ранние дни
2. **По времени начала** (`startTime`) — в пределах одного дня
3. **По порядку** (`sortOrder`) — при одинаковом времени

## Обратная совместимость

⚠️ **Важно:** Данные изменения требуют обновления бэкенда для поддержки поля `date` в API.

Если бэкенд еще не обновлен:
- Поле `date` будет отправляться в запросах
- Могут возникать ошибки валидации (400 Bad Request)
- Необходимо обновить бэкенд согласно новому контракту API

## Миграция существующих данных

Для существующих элементов агенды без поля `date`:
- Бэкенд должен автоматически подставлять `startDate` события
- Или провести миграцию данных для добавления поля `date` ко всем существующим записям
