# Обновление UI/UX системы вопросов

**Дата**: 22 января 2026  
**Версия**: 2.0

## Основное изменение

### Один режим на событие

**Правило**: Для каждого события устанавливается **один тип** вопросов:
- Либо все вопросы обычные (для сбора информации)
- Либо все вопросы тестовые (с баллами)

**Нельзя** смешивать обычные вопросы и тестовые в рамках одного события.

---

## Архитектура

### Состояние режима события

```typescript
// Состояние на уровне EventQuestionsTab
const [eventMode, setEventMode] = useState<'info' | 'test'>('info')

// Определение режима по существующим вопросам
useEffect(() => {
  if (questions.length > 0) {
    const hasTestQuestions = questions.some((q) => q.points > 0)
    setEventMode(hasTestQuestions ? 'test' : 'info')
  }
}, [questions])
```

### Передача режима в диалог

```typescript
<QuestionDialog
  mode={eventMode} // Фиксированный режим для всего события
  // ...
/>
```

## UI/UX Изменения

### 1. Empty State (Нет вопросов)

Когда вопросов нет, пользователь **сначала выбирает режим**:

```
┌─────────────────────────────────────┐
│   🎓 Вопросов пока нет              │
│                                     │
│  ┌─────────────┐  ┌──────────────┐ │
│  │  📄 Вопросы │  │ 🎓 Тесты     │ │
│  │  Сбор       │  │ Проверка     │ │
│  │  информации │  │ знаний       │ │
│  └─────────────┘  └──────────────┘ │
│                                     │
│     [Добавить вопрос]              │
└─────────────────────────────────────┘
```

**Переключатель режима** доступен только когда нет вопросов.

### 2. Wizard (Добавление вопроса)

#### Для режима "Вопросы" (info):
- **1 шаг**: Контент вопроса (формат, текст, опции)
- **Нет второго шага** (настройки теста не нужны)

#### Для режима "Тесты" (test):
- **Шаг 1**: Контент вопроса (формат, текст, опции)
- **Шаг 2**: Настройки теста (баллы, правильные ответы)

**Убрано**:
- Выбор режима (вопрос/тест) в wizard'е
- Шаг "Выберите тип вопроса" в диалоге

### 3. Список вопросов

**Убрано**:
- Табы "Все" / "Вопросы" / "Тесты"
- Разделение вопросов по категориям

**Теперь**:
- Один список всех вопросов
- Индикатор режима в заголовке

```
┌─────────────────────────────────────┐
│ Форма регистрации  [🎓 Тест (50 б)] │
│ 5 вопросов                          │
│                           [Добавить]│
├─────────────────────────────────────┤
│ ┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓ │
│ ┃ Максимальный балл: 50         ┃ │
│ ┃                    5 вопросов ┃ │
│ ┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛ │
│                                     │
│ ┌─ Вопрос 1 ──────────────────┐    │
│ │ 📝 Текст • Открытый • 10 б  │    │
│ └─────────────────────────────┘    │
│                                     │
│ ┌─ Вопрос 2 ──────────────────┐    │
│ │ ☑️  Выбор • Альтернатив • 15 б│    │
│ └─────────────────────────────┘    │
└─────────────────────────────────────┘
```

## Валидация

### Проверка режима при создании вопроса

```typescript
const handleSubmit = (data: QuestionFormValues) => {
  const requestData: Partial<RegistrationQuestion> = {
    question: data.question,
    type: data.type,
    category: data.category,
    isRequired: data.isRequired,
    options: data.options,
    // fixedMode определяет, будет ли points > 0
    points: fixedMode === 'test' ? data.points : 0,
    // ...
  }
}
```

### Динамическое количество шагов

```typescript
const totalSteps = fixedMode === 'test' ? 2 : 1
```

## Поведение компонентов

### QuestionDialog

**Props**:
```typescript
{
  mode: 'info' | 'test'  // Фиксированный режим события
  editingQuestion?: RegistrationQuestion | null
  // ...
}
```

**Логика**:
- `mode` передается сверху и **не изменяется** внутри диалога
- `form.setValue('mode', fixedMode)` устанавливается при инициализации
- Количество шагов зависит от `fixedMode`

### EmptyState

**Props**:
```typescript
{
  eventMode: 'info' | 'test'
  onModeChange: (mode: 'info' | 'test') => void
}
```

**Логика**:
- Позволяет выбрать режим перед добавлением первого вопроса
- Визуально выделяет выбранный режим
- Текст кнопки меняется: "Добавить вопрос" / "Добавить тестовый вопрос"

## Преимущества новой архитектуры

### 1. Упрощение UI
- Убраны лишние шаги и выборы
- Меньше когнитивной нагрузки на пользователя
- Один режим = один тип интерфейса

### 2. Логическая согласованность
- Все вопросы события имеют одну цель
- Либо сбор информации, либо тестирование
- Не смешиваются разные подходы

### 3. Упрощение валидации
- Нет необходимости проверять режим каждого вопроса
- Режим определяется один раз на уровне события

### 4. Улучшенная читаемость кода
- `mode` передается сверху вниз
- Меньше условной логики
- Явное управление состоянием

---

## Миграция данных

**Не требуется**. Существующие вопросы корректно определяются:
- Если `points > 0` → режим "test"
- Если `points === 0` → режим "info"

## Будущие улучшения

### Возможные доработки:

1. **Сохранение режима в настройках события**
   - Добавить поле `questionMode: 'info' | 'test'` в Event
   - Определять режим не по вопросам, а по настройке

2. **Блокировка изменения режима**
   - После добавления первого вопроса заблокировать смену режима
   - Показывать предупреждение при попытке изменить

3. **Шаблоны вопросов**
   - Предустановленные наборы вопросов для "info" и "test"
   - Быстрый старт с готовыми шаблонами

## Заключение

Новая архитектура делает систему вопросов **более понятной и простой в использовании**. Организатор сразу определяет цель: собирать информацию или тестировать участников, и все вопросы подчиняются этой логике.
