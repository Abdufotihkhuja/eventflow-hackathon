# Руководство по системе тестирования

## Обзор

Руководство для организаторов по созданию тестов для отбора и оценки участников мероприятий.

---

## Когда использовать тесты

### Автоматический отбор (AUTO_REJECT)

**Используйте когда**:
- Мероприятие требует определенного уровня знаний
- Ограниченное количество мест
- Нужно автоматически отсеять неподготовленных участников

**Примеры**:
- Продвинутые курсы и воркшопы
- Хакатоны с высоким порогом входа
- Специализированные конференции

### Оценка для организатора (EVALUATION)

**Используйте когда**:
- Нужно оценить уровень участников
- Распределение по группам/потокам
- Подготовка персонализированной программы

**Примеры**:
- Образовательные программы с разными уровнями
- Менторские программы
- Networking события с подбором пар

## Создание теста: пошаговая инструкция

### Шаг 1: Настройка события

При создании мероприятия укажите:

```json
{
  "title": "Advanced JavaScript Workshop",
  "registrationMode": "TEST",
  "testEvaluationType": "AUTO_REJECT",
  "minTestScore": 70
}
```

**Параметры**:
- `registrationMode: "TEST"` - включает режим тестирования
- `testEvaluationType`: 
  - `"AUTO_REJECT"` - не прошедшие отклоняются
  - `"EVALUATION"` - все допускаются, результаты сохраняются
- `minTestScore` - минимальный балл для прохождения (например, 70 из 100)

### Шаг 2: Создание вопросов

#### Открытые вопросы (OPEN)

Для проверки понимания концепций:

```json
{
  "question": "Объясните разницу между var, let и const",
  "type": "TEXTAREA",
  "category": "OPEN",
  "points": 15,
  "correctAnswer": "область видимости,hoisting,переопределение,const неизменяемый",
  "isRequired": true
}
```

**Совет**: В `correctAnswer` укажите ключевые слова через запятую. Если ответ участника содержит хотя бы одно ключевое слово - засчитывается как правильный.

#### Закрытые вопросы (CLOSED)

Для быстрой проверки базовых знаний:

```json
{
  "question": "Является ли JavaScript типизированным языком?",
  "type": "CHECKBOX",
  "category": "CLOSED",
  "options": ["Да", "Нет"],
  "points": 5,
  "correctAnswer": "Да",
  "isRequired": true
}
```

#### Альтернативные вопросы (ALTERNATIVE)

Для проверки конкретных знаний:

**Один правильный ответ (SELECT)**:
```json
{
  "question": "Какой метод используется для добавления элемента в конец массива?",
  "type": "SELECT",
  "category": "ALTERNATIVE",
  "options": ["push", "pop", "shift", "unshift"],
  "correctOptions": ["push"],
  "points": 10,
  "isRequired": true
}
```

**Несколько правильных ответов (CHECKBOX)**:
```json
{
  "question": "Какие из этих методов изменяют исходный массив?",
  "type": "CHECKBOX",
  "category": "ALTERNATIVE",
  "options": ["push", "map", "splice", "filter", "sort"],
  "correctOptions": ["push", "splice", "sort"],
  "points": 15,
  "isRequired": true
}
```

### Шаг 3: Настройка весов вопросов

**Рекомендации по распределению баллов**:

| Сложность | Баллы | Тип вопроса |
|-----------|-------|-------------|
| Базовая | 5-10 | Закрытые, простые альтернативные |
| Средняя | 10-20 | Альтернативные с несколькими ответами |
| Высокая | 20-30 | Открытые вопросы, требующие объяснения |

**Пример распределения для теста на 100 баллов**:
- 5 базовых вопросов × 5 баллов = 25 баллов
- 5 средних вопросов × 10 баллов = 50 баллов
- 1 сложный вопрос × 25 баллов = 25 баллов
- **Итого**: 100 баллов

### Шаг 4: Установка порога прохождения

**Рекомендации**:

| Уровень сложности | Порог | Описание |
|-------------------|-------|----------|
| Базовый | 50-60% | Проверка минимальных знаний |
| Средний | 70-80% | Уверенное владение темой |
| Продвинутый | 85-95% | Экспертный уровень |

**Примеры**:
- Вводный курс: `minTestScore: 50` (из 100)
- Профессиональный воркшоп: `minTestScore: 75` (из 100)
- Экспертная конференция: `minTestScore: 90` (из 100)

## Автоматический расчет баллов

Система автоматически:
1. Суммирует `points` всех вопросов → `maxTestScore`
2. При регистрации проверяет ответы участника
3. Подсчитывает набранные баллы → `testScore`
4. Сравнивает с `minTestScore` → `testPassed`

**Пример**:
- Создано 10 вопросов по 10 баллов каждый
- `maxTestScore` автоматически = 100
- Участник правильно ответил на 8 вопросов
- `testScore` = 80
- Если `minTestScore` = 70 → `testPassed` = true

## Проверка ответов

### Открытые вопросы (OPEN)

**Метод проверки**: поиск ключевых слов

```json
{
  "correctAnswer": "замыкание,область видимости,лексическое окружение"
}
```

Ответ участника: "Замыкание - это функция с доступом к внешней области видимости"

**Результат**: ✅ Правильно (содержит "замыкание" и "область видимости")

### Закрытые вопросы (CLOSED)

**Метод проверки**: точное совпадение

```json
{
  "correctAnswer": "Да"
}
```

Ответ участника: "Да"

**Результат**: ✅ Правильно

### Альтернативные вопросы (ALTERNATIVE)

**Метод проверки**: совпадение множеств

```json
{
  "correctOptions": ["push", "splice", "sort"]
}
```

Ответ участника: "push,splice,sort"

**Результат**: ✅ Правильно (все варианты выбраны верно)

Ответ участника: "push,splice"

**Результат**: ❌ Неправильно (не все варианты выбраны)

## Просмотр результатов

### Для режима AUTO_REJECT

Отклоненные участники получают ошибку при регистрации:

```
Тест не пройден. Набрано 45 из 100 баллов. Требуется минимум 70.
```

Одобренные участники видны в списке регистраций со статусом APPROVED.

### Для режима EVALUATION

Все участники допущены, но в регистрации сохранены:
- `testScore` - набранные баллы
- `testMaxScore` - максимально возможные баллы
- `testPassed` - прошел ли порог
- `testCompletedAt` - когда завершил тест

**Использование**:
- Распределение по группам (начинающие/продвинутые)
- Подбор менторов
- Персонализация программы

## Лучшие практики

### 1. Баланс сложности

✅ **Хорошо**:
- Микс простых, средних и сложных вопросов
- 60% средних, 20% простых, 20% сложных

❌ **Плохо**:
- Только сложные вопросы (высокий отсев)
- Только простые вопросы (не отсеивает)

### 2. Количество вопросов

**Рекомендации**:
- Короткий тест: 5-10 вопросов (5-10 минут)
- Средний тест: 10-20 вопросов (15-20 минут)
- Длинный тест: 20-30 вопросов (30-40 минут)

### 3. Формулировка вопросов

✅ **Хорошо**:
- "Какой метод добавляет элемент в конец массива?"
- Четкий, однозначный вопрос

❌ **Плохо**:
- "Что вы думаете о массивах в JavaScript?"
- Слишком общий, субъективный

### 4. Варианты ответов

✅ **Хорошо**:
- 4-5 вариантов для SELECT
- Все варианты правдоподобны
- Нет очевидно неправильных

❌ **Плохо**:
- 2 варианта (угадывание 50/50)
- Один вариант явно абсурдный

### 5. Порог прохождения

✅ **Хорошо**:
- Адекватный уровню мероприятия
- Протестирован на нескольких людях

❌ **Плохо**:
- 95% для вводного курса
- 40% для экспертной конференции

## Часто задаваемые вопросы

### Можно ли изменить minTestScore после создания события?

Да, через PATCH `/api/v1/events/:id`:

```json
{
  "minTestScore": 80
}
```

### Что происходит при удалении вопроса?

Система автоматически пересчитывает `maxTestScore` события.

### Можно ли комбинировать тестовые и нетестовые вопросы?

Да! Вопросы с `points: 0` не участвуют в подсчете, но ответы сохраняются.

### Как участник видит результаты теста?

В режиме AUTO_REJECT - только при отклонении (в ошибке).
В режиме EVALUATION - результаты видны организатору, не участнику.
